## Задание
### MemcLoad (Go версия)

*Задание*: конкурентная обработка поминутной выгрузки логов трекера установленных приложений и загрузка в Memcached. Ключом является тип и идентификатор устройства через двоеточие, значением — protobuf-сериализованное сообщение.

Исходная Python-верция: `memc_load.py`.

## Структура проекта

```
.
├── main.go           # точка входа, парсинг CLI, основной цикл
├── parser.go         # парсинг TSV строк и сериализация protobuf
├── memcached.go      # пул подключений к Memcached
├── worker.go         # конкурентная обработка файлов и строк
├── parser_test.go    # тесты парсера и сериализации
├── worker_test.go    # тесты обработки и интеграции
├── go.mod            # модуль Go
├── go.sum            # чексуммы зависимостей
├── cmd/
│   └── gen_sample/
│       └── main.go   # генератор тестовых TSV.gz файлов
├── sample.tsv        # пример данных
└── README.md
```

## Установка

Требуется Go 1.21+.

```sh
go mod download
```

## Генерация тестовых данных

```sh
go run ./cmd/gen_sample --dir=.
```

Будет создано 3 файла `YYYYMMDDHHMMSS.tsv.gz` по ~512 MiB каждый.

## Запуск

### Тестовый запуск (dry run)

```sh
go run . --pattern='*.tsv.gz' --dry
```

### Боевой запуск

```sh
go build -o memcload .

./memcload \
    --pattern=/data/appsinstalled/*.tsv.gz \
    --idfa=memcached1:11211 \
    --gaid=memcached2:11211 \
    --adid=memcached3:11211 \
    --dvid=memcached4:11211 \
    --workers=16
```

### Тест сериализации

```sh
go run . --test
```

## Тесты

```sh
go test -v -race -count=1 ./...
```

## Параметры командной строки

| Параметр | Описание | Значение по умолчанию |
|----------|----------|----------------------|
| `--pattern` | Паттерн для поиска TSV.gz файлов | `/data/appsinstalled/*.tsv.gz` |
| `--dry` | Режим сухого запуска (только логирование) | `false` |
| `--workers` | Количество рабочих горутин | `16` |
| `--idfa` | Адрес Memcached для IDFA устройств | `127.0.0.1:33013` |
| `--gaid` | Адрес Memcached для GAID устройств | `127.0.0.1:33014` |
| `--adid` | Адрес Memcached для ADID устройств | `127.0.0.1:33015` |
| `--dvid` | Адрес Memcached для DVID устройств | `127.0.0.1:33016` |
| `--log` | Путь к файлу логов | `stdout` |
| `--test` | Запуск теста сериализации | `false` |

## Архитектура

### Конкурентная обработка с горутинами

Вместо `ThreadPoolExecutor` из Python используется идиоматичный подход Go:
- **Горутины** для параллельной обработки строк
- **Канал-семафор** (`chan struct{}`) для ограничения количества одновременных горутин
- **`sync/atomic`** для безблокировочного подсчёта статистики
- **`sync.WaitGroup`** для ожидания завершения всех горутин

### Ключевые особенности

- Файлы обрабатываются последовательно в хронологическом порядке (сортировка по имени)
- Строки внутри каждого файла обрабатываются параллельно с ограничением `--workers`
- После обработки файла он переименовывается с префиксом `.` для отслеживания прогресса
- Подключения к Memcached кэшируются в пуле `MemcachedPool` (thread-safe через `sync.RWMutex`)

### Сериализация

Вместо внешней зависимости `protobuf` реализован собственный сериализатор, совместимый с wire format Protocol Buffers:
- `varint` кодирование для целых чисел
- `fixed64` для float64 (latitude, longitude)
- `length-delimited` для repeated полей (packed varint)

## Идиоматичность Go

- **Структуры вместо namedtuple**: `AppsInstalled` как `struct`
- **Ошибки как значения**: функции возвращают `*AppsInstalled` и `nil` при ошибках
- **`sync.RWMutex`** для thread-safe пула клиентов
- **Double-check locking** в `GetClient`
- **Каналы как семафоры** для ограничения параллелизма
- **`flag` пакет** вместо `optparse`
- **`log` пакет** с форматированием вместо `logging`
- **`bufio.Scanner`** для эффективного чтения файлов
- **`compress/gzip`** для работы с gzip
- **`math.Float64bits`** для бинарного представления float64
